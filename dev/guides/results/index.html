Results

estimate returns a vector of ParameterEstimationResults, best fit first.

using ODEParameterEstimation, ModelingToolkit
using ModelingToolkit: t_nounits as t, D_nounits as D

@parameters a b
@variables x1(t) x2(t) y1(t) y2(t)
@named oscillator = System([D(x1) ~ -a * x2, D(x2) ~ b * x1], t)

problem = ParameterEstimationProblem(oscillator, [y1 ~ x1, y2 ~ x2];
    true_values = [a => 0.4, b => 0.9, x1 => 1.0, x2 => 0.5])
problem = sample_problem_data(problem; datasize = 41, time_interval = [0.0, 5.0])

results = estimate(problem)
1-element Vector{ParameterEstimationResult}:
 ParameterEstimationResult(a = 0.4, b = 0.9; x1(t) = 1, x2(t) = 0.5)

One result

best = results[1]
ParameterEstimationResult
  Parameters
    a = 0.4
    b = 0.9
  Initial conditions (t = 0)
    x1(t) = 1
    x2(t) = 0.5
  Fit error: 3.45e-26

The printout has the parameters, the initial conditions with the time they belong to, and the fit error. The values can be taken out by symbol or by name:

best[a], best[:b], best["x1"]
(0.4000000000000009, 0.8999999999999815, 1.0000000000000009)

or all at once, as dictionaries keyed by symbol:

best.parameters
OrderedCollections.OrderedDict{Symbolics.Num, Float64} with 2 entries:
  a => 0.4
  b => 0.9
best.states
OrderedCollections.OrderedDict{Symbolics.Num, Float64} with 2 entries:
  x1(t) => 1.0
  x2(t) => 0.5

best.err is the fit error: the sum of squared differences between the data and the model simulated with these values. It is what results are ranked by. Use it to compare the results of one run with each other.

Using the estimates

best.states and best.parameters are in the form ModelingToolkit takes, so simulating the fitted model is one line:

using OrdinaryDiffEq

fitted = solve(ODEProblem(mtkcompile(oscillator), merge(best.states, best.parameters), (0.0, 5.0)), Tsit5())

Seeing the fit plots such a simulation against the data.

Several results

When the vector holds more than one result, each is a different set of values that fits the data. When a result marks some values not identifiable, the data do not determine them. More than one answer covers both.

An empty vector means no solution was found. See Troubleshooting.

When the true values are known

For testing a model or the method, analyze_parameter_estimation_problem returns the results together with a comparison against the problem's true values:

raw, analysis, uq = analyze_parameter_estimation_problem(problem, EstimationOptions())
analysis.best_max_error
3.7969627442180354e-14

analysis.returned_results is what estimate returns. best_max_error is the largest relative error over the parameters and initial conditions, for the candidate solution that came closest to the truth. That candidate is usually the first result, but it does not have to be, so to score the first result itself, compare its values with the truth directly.

Where a result came from

Each result records how it was produced. best.interpolator_source names the curve fit whose derivative estimates led to it, and best.provenance holds the rest: which time point it was solved at and whether it was refined afterwards.
